# 环境配置

本文分为两个部分：**WASM Mod 开发环境**（编写和编译游戏 Mod）和**从源码编译框架**（修改 SoupRune 框架本身）。大多数内容创作者只需要前者。

---

## 第一部分：WASM Mod 开发环境

这是大多数 Mod 开发者需要的环境。配置完成后即可编写自定义行为模块，编译为 WASM 并在 SoupRune 中运行。

### Rust 工具链

SoupRune 的 Mod 系统当前使用 Rust 编写。安装 Rust stable 工具链：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

验证安装：

```bash
rustc --version     # 需要 1.86+
cargo --version
```

### WASM 编译目标

```bash
rustup target add wasm32-wasip2
```

### 代码编辑器（推荐）

| 编辑器       | 推荐插件                            |
|-----------|---------------------------------|
| VS Code   | rust-analyzer, Even Better TOML |
| RustRover | 内置 Rust 支持                      |
| Neovim    | rust-analyzer (LSP)             |

### 创建 Mod 项目

WASM Mod 使用 `souprune_sdk` crate 和 `wit-bindgen` 生成绑定。参考 `crates/souprune_mod_test/` 的结构。

### 编译与测试

```bash
# 编译 WASM Mod
cargo build -p souprune_mod_test --target wasm32-wasip2

# 独立测试（使用 mock host）
cargo run -p souprune_mock_host
```

编译产物 `.wasm` 文件放入 Mod 目录，并在 `mod.toml` 中配置：

```toml
[mod_library]
wasm = "my_mod.wasm"
```

### 未来语言支持

SoupRune 的 Mod 系统基于 WASM Component Model，理论上支持任何能编译到 `wasm32-wasip2` 的语言。计划中的语言支持：

| 语言             | 状态     | 说明                              |
|----------------|--------|---------------------------------|
| **Rust**       | ✅ 可用   | 通过 `souprune_sdk`，性能最佳          |
| **C# (.NET)**  | 🚧 计划中 | NativeAOT → WASM，适合 Unity 开发者迁移 |
| **JavaScript** | 🚧 计划中 | 降低入门门槛                          |

## 第二部分：从源码编译框架

如果你需要修改 SoupRune 框架本身、运行示例项目或参与框架开发，需要以下环境。

> **注意**：纯 Mod 开发者不需要编译整个框架。只有框架贡献者或需要调试框架行为的人才需要此部分。

### 系统依赖

#### Linux

**Arch Linux / Manjaro：**

```bash
sudo pacman -S base-devel pkg-config libx11 alsa-lib systemd-libs \
    wayland libxkbcommon
```

**Ubuntu / Debian：**

```bash
sudo apt-get install -y g++ pkg-config libx11-dev libasound2-dev libudev-dev \
    libwayland-dev libxkbcommon-dev
```

#### Windows

- Visual Studio Build Tools（C++ 工作负载）
- 或 MinGW-w64

#### macOS

```bash
xcode-select --install
```

### Rust 工具链

如果你已经按照第一部分安装了 Rust，可以跳过。否则：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

### Git

需要 Git 来克隆仓库和管理 submodule：

```bash
# Arch Linux
sudo pacman -S git

# Ubuntu/Debian
sudo apt-get install git

# macOS（已随 Xcode CLI Tools 安装）
git --version

# Windows：从 https://git-scm.com/ 下载
```

### 获取源码

```bash
# 克隆仓库
git clone https://github.com/Bli-AIk/souprune.git
cd souprune

# 初始化 Git submodule（bevy_fact_rule_event, bevy_mortar_bond 等）
git submodule update --init --recursive
```

> **注意**：submodule 包含了 FRE、Mortar、AM 等核心 crate 的源码。如果跳过这一步，编译会失败。

### 获取示例 Mod

示例 Mod 通过 Git worktree 管理，使用内置脚本安装：

```bash
# 查看可用的 Mod
./setup_mods.sh --list

# 安装所有示例 Mod
./setup_mods.sh

# 仅安装特定 Mod
./setup_mods.sh example_mod

# 更新已安装的 Mod
./setup_mods.sh --update
```

### 编译与运行

```bash
# 首次编译（5-15 分钟，取决于机器配置）
cargo build --workspace

# 运行当前活动 Mod
cargo run -p souprune

# 带调试功能运行（Inspector + 性能 HUD）
cargo run -p souprune --features debug
```

`--features debug` 会启用：

- `bevy-inspector-egui`：运行时 ECS 实体/组件检查器
- `iyes_perf_ui`：帧率和性能指标 HUD
- 额外的调试日志输出

### 开发命令速查

```bash
cargo test --workspace                                   # 运行测试
cargo fmt --all                                          # 代码格式化
cargo clippy --workspace --all-targets -D warnings       # 静态检查
```

## 常见问题

### `cargo` 命令找不到

确认 Rust 已安装且 `~/.cargo/bin` 在 PATH 中：

```bash
source "$HOME/.cargo/env"
```

### 编译时找不到系统库

Linux 上通常是缺少开发头文件。按照"系统依赖"部分安装所有包。

### 编译速度慢

- 推荐使用 `mold`（Linux）或 `lld` 链接器加速链接阶段
- 可配置 `.cargo/config.toml` 启用并行编译

### Submodule 相关错误

```bash
# 重置并重新初始化
git submodule deinit --all -f
git submodule update --init --recursive
```

### 窗口黑屏 / GPU 相关错误

- 确认显卡驱动是最新版本
- Wayland 用户：尝试设置环境变量 `WINIT_UNIX_BACKEND=x11` 回退到 X11
