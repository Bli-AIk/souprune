# Mortar 战斗对话入门

## 什么是 Mortar？

Mortar 是 SoupRune 使用的对话脚本语言，专为游戏叙事场景设计。在战斗系统中，Mortar 负责：

- **ACT 对话**：玩家选择"查看""交谈"等行为后显示的文本
- **MERCY 对话**：饶恕或逃跑时的文本反馈
- **UI 常量**：按钮标签、敌人名称等本地化文本
- **战斗旁白**：遭遇开始时的叙述文本

Mortar 的设计目标是让非程序员也能编写游戏对话。语法简单直觉，类似于标记语言而非编程语言。

> **Mortar 官方文档**（完整语法参考）：
> https://bli-aik.github.io/mortar/
>
> 本文不会重复官方文档的内容，仅聚焦于**战斗系统中的实际用法**。

## 文件组织

战斗相关的 Mortar 文件位于 Mod 的 `shared/locales/` 目录下，按语言分组：

```
shared/locales/
├── en-US/
│   └── battle/
│       ├── ui.mortar              # UI 常量（按钮标签、敌人名称）
│       └── enemies/
│           ├── dummy.mortar       # 假人的 ACT/MERCY 对话
│           ├── froggit.mortar     # 蛙吉特的对话
│           └── ...
└── zh-Hans/
    └── battle/
        ├── ui.mortar              # 同上，中文版
        └── enemies/
            ├── dummy.mortar
            ├── froggit.mortar
            └── ...
```

注意：**同一个文件在每种语言目录下都有一份**，结构完全对称。切换语言时框架会自动加载对应目录的文件。

## UI 常量：`battle/ui.mortar`

`ui.mortar` 是战斗系统的"字符串表"。它使用 `pub const` 声明公共常量，框架在加载时会将这些常量提取到 `MortarStringTable` 中供
UI 和 FRE 规则引用。

### 基础 UI 标签

```mortar
pub const LV: String = "LV"
pub const HP: String = "HP"
```

这些常量被 View 系统用于渲染 HUD 文本。

### 敌人名称

```mortar
pub const ENEMY_DUMMY: String = "Dummy"
pub const ENEMY_FROGGIT: String = "Froggit"
pub const ENEMY_WHIMSUN: String = "Whimsun"
```

敌人名称在战斗界面的多个位置显示（选择框、信息栏等），通过常量集中管理而非硬编码在 RON 配置中。

### ACT 选项标签

每个敌人的 ACT 选项需要在 `ui.mortar` 中定义标签：

```mortar
// ACT 选项标签 - Dummy (4 个选项)
pub const ACT_DUMMY_CHECK: String = "Check"
pub const ACT_DUMMY_TALK: String = "Talk"
pub const ACT_DUMMY_FLIRT: String = "Flirt"
pub const ACT_DUMMY_HUG: String = "Hug"
```

命名规则为 `ACT_{敌人名}_{行为名}`。这些常量的值就是显示在 ACT 菜单中的按钮文字。

### MERCY 选项标签

```mortar
pub const MERCY_SPARE: String = "Spare"
pub const MERCY_FLEE: String = "Flee"
```

### 战斗开场旁白

可以用常量或节点两种方式定义开场文本：

```mortar
// 常量方式 — 直接引用
pub const ENEMY_APPEARED: String = "* Whimsun approached meekly!"

// 节点方式 — 支持打字机效果和事件绑定
node encounter_intro {
    text: "* Whimsun approached meekly!"
}
```

节点方式更灵活，支持多行文本、条件分支和事件触发。常量方式更简洁，适合静态文本。

## 敌人对话：`battle/enemies/*.mortar`

每个敌人有独立的 `.mortar` 文件，包含该敌人所有 ACT 和 MERCY 行为对应的对话节点。

### 节点命名约定

节点名称与 FRE 规则中的引用一一对应：

| 节点名           | 用途         |
|---------------|------------|
| `act_check`   | 查看（显示敌人属性） |
| `act_talk`    | 交谈         |
| `act_flirt`   | 调情         |
| `mercy_spare` | 饶恕         |
| `act_{行为名}`   | 其他自定义 ACT  |

### 示例：Dummy 对话

```mortar
// 文件：battle/enemies/dummy.mortar

node act_check {
    text: "* DUMMY - ATK 0 DEF 0"
    text: "* A cotton heart and a button eye."
    text: "* You are the apple of my eye."
}

node act_talk {
    text: "* You talk to Dummy."
    text: "* It doesn't seem like much of a conversation."
}

node act_flirt {
    text: "* You flirt with Dummy."
    text: "* Its face is red... Is that dye?"
}

node act_hug {
    text: "* You hug Dummy."
    text: "* ..."
}

node mercy_spare {
    text: "* You spared Dummy."
    text: "* Dummy feels relieved."
}
```

每个 `text:` 语句是一段独立的对话文本。玩家按确认键后推进到下一个 `text:`。

### 示例：更复杂的敌人

以下方怪物为例，它有 6 个 ACT 选项：

```mortar
// 文件：battle/enemies/vegetoid.mortar

node act_check {
    text: "* VEGETOID - ATK 6 DEF 6"
    text: "* Serving Size: 1 Monster"
    text: "* Not monitored by the USDA"
}

node act_dinner {
    text: "* You pat your stomach."
    text: "* Vegetoid offers a healthy meal."
}

node act_devour {
    text: "* You tried to eat Vegetoid, but it wasn't weakened enough."
}

node act_flirt {
    text: "* You wink at Vegetoid."
    text: "* Vegetoid seems confused but flattered."
}
```

注意 `act_devour` 只有一行文本，这完全合法——节点中 `text:` 的数量没有限制。

## FRE 如何触发 Mortar 对话

Mortar 文件本身只是"剧本"。真正决定**何时播放哪段对话**的是 FRE 规则，通过 `StartDialogue` 动作连接二者。

```ron
// 在 .fre.ron 文件中
(
    id: "act_dummy_check",
    event: Event("battle:execute_act"),
    conditions: ["$act_type == 'check'", "$target_enemy == 'dummy'"],
    actions: [
        StartDialogue(
            mortar: "battle/enemies/dummy.mortar",
            node: "act_check",
            focus: true,
            typewriter: true,
            voice: "audios/voice/voice_typewriter_default.wav",
        ),
    ],
    priority: 10,
)
```

`StartDialogue` 的参数：

| 参数           | 类型               | 说明                                      |
|--------------|------------------|-----------------------------------------|
| `mortar`     | String           | Mortar 文件路径（相对于 `shared/locales/{语言}/`） |
| `node`       | String           | 要播放的节点名称                                |
| `typewriter` | bool             | 是否使用打字机效果逐字显示（默认 `true`）                |
| `focus`      | bool             | 对话框是否接管输入焦点（默认 `true`）                  |
| `voice`      | Option\<String\> | 打字机音效文件路径（可选）                           |
| `view`       | Option\<String\> | 自定义对话 View（可选，默认使用战斗对话框）                |

> 关于 FRE 规则的详细说明，请参阅 [[1.4_act|编写交互逻辑]]。

## 本地化

Mortar 的本地化通过**目录结构**实现，而非文件内的多语言字段。

### 工作原理

1. `projects/config.toml` 中指定当前语言：

```toml
[project]
mod_name = "example_mod"
language = "en-US"
```

2. 框架加载 `shared/locales/{language}/` 目录下的所有 `.mortar` 文件
3. FRE 规则中的 `mortar:` 路径（如 `"battle/enemies/dummy.mortar"`）会自动在当前语言目录下查找

### 添加新语言

要添加中文支持，只需在 `zh-Hans/` 下创建对应文件，翻译所有文本：

**`en-US/battle/enemies/dummy.mortar`：**

```mortar
node act_check {
    text: "* DUMMY - ATK 0 DEF 0"
    text: "* A cotton heart and a button eye."
}
```

**`zh-Hans/battle/enemies/dummy.mortar`：**

```mortar
node act_check {
    text: "* DUMMY - ATK 0 DEF 0"
    text: "* 棉花心和纽扣眼。"
}
```

两个文件的**节点名称必须完全一致**，只翻译 `text:` 的内容。FRE 规则不需要任何修改——它引用的节点名是语言无关的。

### UI 常量的本地化

`ui.mortar` 中的常量同样需要翻译：

**`en-US/battle/ui.mortar`：**

```mortar
pub const ACT_DUMMY_CHECK: String = "Check"
pub const ACT_DUMMY_TALK: String = "Talk"
pub const MERCY_SPARE: String = "Spare"
```

**`zh-Hans/battle/ui.mortar`：**

```mortar
pub const ACT_DUMMY_CHECK: String = "检查"
pub const ACT_DUMMY_TALK: String = "交谈"
pub const MERCY_SPARE: String = "饶恕"
```

常量名保持一致，值替换为翻译文本。

## 完整工作流示例

以新增一个名为 "Icecap" 的敌人为例，展示从零开始添加战斗对话的完整步骤。

### 1. 创建对话文件

**`en-US/battle/enemies/icecap.mortar`：**

```mortar
node act_check {
    text: "* ICECAP - ATK 7 DEF 2"
    text: "* This teen wears a hat that's too cool for words."
}

node act_compliment {
    text: "* You tell Icecap you like its hat."
    text: "* Icecap smugly adjusts its hat."
}

node act_steal {
    text: "* You steal Icecap's hat!"
    text: "* Icecap becomes insecure..."
}

node mercy_spare {
    text: "* You spared Icecap."
}
```

### 2. 注册 UI 常量

**`en-US/battle/ui.mortar`**（追加）：

```mortar
pub const ENEMY_ICECAP: String = "Icecap"

pub const ACT_ICECAP_CHECK: String = "Check"
pub const ACT_ICECAP_COMPLIMENT: String = "Compliment"
pub const ACT_ICECAP_STEAL: String = "Steal Hat"
```

### 3. 编写 FRE 规则

在对应的 `.fre.ron` 文件中添加规则，将 ACT 事件与 Mortar 节点关联：

```ron
(
    id: "act_icecap_check",
    event: Event("battle:execute_act"),
    conditions: ["$act_type == 'check'", "$target_enemy == 'icecap'"],
    actions: [
        StartDialogue(
            mortar: "battle/enemies/icecap.mortar",
            node: "act_check",
        ),
    ],
    priority: 10,
),
(
    id: "act_icecap_compliment",
    event: Event("battle:execute_act"),
    conditions: ["$act_type == 'compliment'", "$target_enemy == 'icecap'"],
    actions: [
        StartDialogue(
            mortar: "battle/enemies/icecap.mortar",
            node: "act_compliment",
        ),
    ],
    modifications: [
        Set(key: "icecap:complimented", value: Bool(true)),
    ],
    priority: 10,
),
```

### 4. 创建翻译版本

**`zh-Hans/battle/enemies/icecap.mortar`：**

```mortar
node act_check {
    text: "* 冰帽怪 - 攻击 7 防御 2"
    text: "* 这个少年戴着一顶酷到无法形容的帽子。"
}

node act_compliment {
    text: "* 你告诉冰帽怪你喜欢它的帽子。"
    text: "* 冰帽怪得意地整了整帽子。"
}

node act_steal {
    text: "* 你偷了冰帽怪的帽子！"
    text: "* 冰帽怪变得不自信了……"
}

node mercy_spare {
    text: "* 你饶恕了冰帽怪。"
}
```

## 注意事项

- **节点名是合同**：FRE 规则通过节点名引用对话。改名需要同步更新所有 `.fre.ron` 引用
- **常量名是键**：`pub const` 的名称在所有语言版本中必须一致，只翻译值
- **一个敌人一个文件**：每个 `enemies/` 下的 `.mortar` 文件对应一个敌人的所有对话
- **路径是相对的**：`StartDialogue` 的 `mortar:` 路径相对于 `shared/locales/{language}/`
- **不需要声明函数**：战斗对话通常不使用自定义函数。函数调用、条件分支等高级特性将在后续章节介绍
