# ACT/MERCY 交互与 FRE 规则

> 涉及类型：`souprune_schema::enemy::ActionOption`、`bevy_fact_rule_event`、`souprune::core::game_action`
>
> 涉及文件：`.fre.ron`、`.enemy.ron`、`.sequence.ron`

## 概述

Undertale 式战斗的核心交互循环是：**玩家在菜单中选择行动 → 执行行动 → 敌人回合（弹幕）→ 循环**。

在 SoupRune 中，这个循环完全由 **FRE（Fact-Rule-Event）规则引擎** 驱动——菜单导航、选项确认、行动执行全部是声明式的 RON 规则，没有硬编码逻辑。

### 数据流概览

```
玩家按键 → FactEvent("action:confirm:just_pressed")
    ↓
FRE 规则引擎匹配触发器 + 评估条件
    ↓
执行动作：SetLocalFact("pending_sequence", ...)
    ↓
Sequencer 读取 pending_sequence → 执行对应 .sequence.ron
    ↓
序列触发对话（Mortar）、旁白、弹幕等
```

## FRE 规则文件结构

**文件**：`states/battle/rules/<name>.fre.ron`

```ron
(
    scope: View,           // 规则作用域：绑定到当前 View 实体
    enums: { ... },        // 枚举常量定义
    facts: { ... },        // 初始 Fact 值（可选）
    rules: [ ... ],        // 规则列表
)
```

### 作用域 (Scope)

| 值 | 说明 |
|----|------|
| `Global` | 全局规则，始终生效 |
| `Local` | 局部规则，与特定序列绑定 |
| `View` | 视图规则，与 View 实体的生命周期绑定 |

战斗菜单规则使用 `View` 作用域——当战斗 UI 生成时注册规则，UI 销毁时自动清理。

### 枚举 (Enums)

枚举为整数值提供可读的别名：

```ron
enums: {
    "depth": ["main", "submenu", "options"],
    // "main" = 0, "submenu" = 1, "options" = 2
    
    "menu_context": ["fight", "act", "item", "mercy"],
    // "fight" = 0, "act" = 1, "item" = 2, "mercy" = 3
},
```

在条件和动作中使用枚举名而非数字：`$depth == 'main'`、`SetLocalFact("depth", Enum("submenu"))`。

## 菜单导航规则

以下是 `undertale_preset` 中的菜单导航规则，展示了如何处理方向键输入：

```ron
// 主菜单：← 向左移动选择
(
    event: ActionEvent(action: "Left", kind: JustPressed),
    conditions: [
        "$interactable == true",    // 菜单可交互
        "$depth == 'main'",         // 在主菜单层级
        "$button_selection > 0",    // 不在最左边
    ],
    actions: [
        SetLocalFact("button_selection", Expr("$button_selection - 1")),
        PlaySound("choice"),
    ],
),

// 主菜单：→ 向右移动选择
(
    event: ActionEvent(action: "Right", kind: JustPressed),
    conditions: [
        "$interactable == true",
        "$depth == 'main'",
        "$button_selection < 3",    // 最多 4 个按钮（0–3）
    ],
    actions: [
        SetLocalFact("button_selection", Expr("$button_selection + 1")),
        PlaySound("choice"),
    ],
),
```

### 规则的组成部分

| 字段 | 说明 |
|------|------|
| `event` | 触发器：`ActionEvent(action, kind)` 监听输入事件 |
| `conditions` | 条件列表（全部为真时规则触发） |
| `actions` | 动作列表（规则触发后依次执行） |
| `priority` | 优先级（越高越先评估，默认 0） |
| `consume_event` | 是否消费事件（阻止低优先级规则触发） |

### 条件表达式语法

```ron
"$interactable == true"          // 布尔比较
"$depth == 'main'"               // 枚举比较（'main' = 0）
"$button_selection > 0"          // 数值比较
"$button_selection < 3"          // 数值比较
"$menu_context != 'item'"        // 不等于
"$enemy_selection > $enemy_view_offset"  // Fact 间比较
```

前缀 `$` 引用 Fact 数据库中的值。支持 `==`、`!=`、`>`、`<`、`>=`、`<=` 运算符。

## 菜单确认与行动执行

确认规则处理从主菜单到子菜单，再到具体行动的层级跳转：

### 主菜单 → 子菜单

```ron
(
    event: ActionEvent(action: "Confirm", kind: JustPressed),
    conditions: ["$interactable == true", "$depth == 'main'"],
    actions: [
        SetLocalFact("menu_context", Expr("$button_selection")),
        SetLocalFact("depth", Enum("submenu")),
        SetLocalFact("enemy_selection", Int(0)),
        PlaySound("confirm"),
    ],
),
```

`menu_context` 保存了玩家选择的菜单类别（fight/act/item/mercy），后续规则根据此值执行不同逻辑。

### ACT 子菜单 → ACT 选项列表

这里展示了 FRE 最强大的特性——**动态 Fact 键访问**：

```ron
(
    event: ActionEvent(action: "Confirm", kind: JustPressed),
    conditions: [
        "$interactable == true",
        "$depth == 'submenu'",
        "$menu_context == 'act'",
    ],
    actions: [
        // 获取当前选中敌人的 ID
        SetLocalFact("current_enemy_id",
            Expr("$enemy_ids[$enemy_selection]")),
        
        // 动态键访问：${current_enemy_id} 会展开为实际敌人 ID
        SetLocalFact("act_count",
            Expr("$${current_enemy_id}.act_count")),
        SetLocalFact("action_labels",
            Expr("$${current_enemy_id}.action_labels")),
        SetLocalFact("action_sequences",
            Expr("$${current_enemy_id}.action_sequences")),
        SetLocalFact("action_params",
            Expr("$${current_enemy_id}.action_params")),
        
        SetLocalFact("depth", Enum("options")),
        SetLocalFact("act_selection", Int(0)),
        PlaySound("confirm"),
    ],
),
```

#### 动态键访问详解

```
表达式: $${current_enemy_id}.act_count
    ↓
1. 解析 ${current_enemy_id} → 查询 Fact "current_enemy_id"
    ↓
2. 得到值 "dummy_0"
    ↓
3. 构建最终键 "dummy_0.act_count"
    ↓
4. 查询 Fact "dummy_0.act_count" → Int(4)
```

这就是为什么 `.enemy.ron` 中的数据会被投射到 FRE Fact 数据库（参见 [1.1 战斗系统配置](1.1_forms.serious.md)）——它使得每个敌人的 ACT/MERCY 选项可以在规则中被动态访问。

### ACT 选项确认 → 执行序列

```ron
(
    event: ActionEvent(action: "Confirm", kind: JustPressed),
    conditions: [
        "$interactable == true",
        "$depth == 'options'",
        "$menu_context == 'act'",
    ],
    actions: [
        SetLocalFact("action_param",
            Expr("$${current_enemy_id}.action_params[$act_selection]")),
        SetLocalFact("mortar_path",
            Expr("$${current_enemy_id}.mortar_path")),
        SetLocalFact("pending_sequence",
            Expr("$${current_enemy_id}.action_sequences[$act_selection]")),
        
        SetLocalFact("selection_confirmed", Bool(true)),
        SetLocalFact("interactable", Bool(false)),
        PlaySound("confirm"),
    ],
),
```

此规则执行后：
1. `pending_sequence` 被设置为对应 ACT 选项的序列路径
2. `selection_confirmed` 变为 `true`
3. 主序列中的 `AwaitFact(condition: "$selection_confirmed == true")` 解除阻塞
4. `RunSequence(path_fact: "pending_sequence")` 读取路径并执行子序列

## 可用动作类型 (GameActionDef)

| 动作 | 说明 | 示例 |
|------|------|------|
| `SetLocalFact(key, value)` | 设置 View 局部 Fact | `SetLocalFact("depth", Enum("submenu"))` |
| `EmitEvent(id)` | 触发 FRE 事件 | `EmitEvent("battle_action_executed")` |
| `PlaySound(name)` | 播放音效 | `PlaySound("confirm")` |
| `PlaySoundFullPath(path)` | 指定完整路径播放音效 | `PlaySoundFullPath("audios/sfx/hit.wav")` |
| `CloseView` | 关闭当前 View | — |
| `SwitchState(state)` | 切换应用状态 | `SwitchState("overworld")` |
| `StartDialogue { ... }` | 启动 Mortar 对话 | 见下方 |
| `UseItem { index_expr }` | 使用物品 | `UseItem(index_expr: "$item_selection")` |

### StartDialogue

启动 Mortar 对话引擎：

```ron
StartDialogue(
    mortar: "battle/enemies/dummy.mortar",  // Mortar 脚本路径
    node: "act_check",                       // 入口节点名
    view: "states/battle/view/dialogue.view.ron",  // 对话 View（可选）
    typewriter: true,                        // 打字机效果（默认 true）
    focus: true,                             // 聚焦对话 View（默认 true）
    voice: "dummy_voice",                    // 语音 ID（可选）
)
```

Mortar 脚本语言的完整文档参见：
- [English](https://bli-aik.github.io/mortar/en)
- [中文](https://bli-aik.github.io/mortar/zh-hans/)

## Fact 值类型

在动作中设置 Fact 时可用的值类型：

```ron
Int(42)                                   // 整数
Float(3.14)                               // 浮点数
Bool(true)                                // 布尔
String("hello")                           // 字符串
Enum("submenu")                           // 枚举名（解析为对应整数）
Expr("$button_selection + 1")             // 运行时表达式
Expr("$enemy_ids[$enemy_selection]")      // 数组索引
Expr("$${current_enemy_id}.act_count")   // 动态键
```

## 输入事件映射

玩家按键会被转换为 FRE 事件：

| 输入 | FRE 事件 ID |
|------|-------------|
| 方向键 ← | `action:left:just_pressed` |
| 方向键 → | `action:right:just_pressed` |
| 方向键 ↑ | `action:up:just_pressed` |
| 方向键 ↓ | `action:down:just_pressed` |
| 确认键 (Z) | `action:confirm:just_pressed` |
| 取消键 (X) | `action:cancel:just_pressed` |

在规则中通过 `ActionEvent` 监听：

```ron
event: ActionEvent(action: "Confirm", kind: JustPressed),
// 等效于匹配 "action:confirm:just_pressed" 事件
```

## 完整交互流程示例

以下是玩家选择 ACT → Check 的完整流程：

```
1. 主菜单显示 [FIGHT] [ACT] [ITEM] [MERCY]
   Fact 状态: depth=main, button_selection=0, interactable=true
   
2. 玩家按 → → 到 ACT (button_selection=1)
   规则匹配: "Right + main + selection<3" → selection += 1
   
3. 玩家按确认键
   规则匹配: "Confirm + main"
   → menu_context = 1 (act), depth = submenu
   
4. 敌人列表显示 [Dummy] [Test1]
   Fact 状态: depth=submenu, menu_context=act, enemy_selection=0
   
5. 玩家按确认键选择 Dummy
   规则匹配: "Confirm + submenu + act"
   → current_enemy_id = "dummy_0"
   → 动态加载: act_count=4, action_labels=["Check","Talk","Flirt","Hug"]
   → depth = options
   
6. ACT 选项显示 [Check] [Talk] [Flirt] [Hug]
   Fact 状态: depth=options, menu_context=act, act_selection=0
   
7. 玩家按确认键选择 Check
   规则匹配: "Confirm + options + act"
   → pending_sequence = "states/battle/common/narration.sequence.ron"
   → action_param = "act_check"
   → selection_confirmed = true
   
8. 主序列解除阻塞
   AwaitFact($selection_confirmed == true) → 通过
   RunSequence(path_fact: "pending_sequence")
   → 执行 narration.sequence.ron，使用 param "act_check"
   
9. 序列执行旁白/对话
   → StartDialogue(mortar: "battle/enemies/dummy.mortar", node: "act_check")
   → "* ATK 0 DEF 0\n* A cotton heart and a button eye.\n* You won't get through to him."
   
10. 对话结束 → 返回主序列 → 进入敌人回合（弹幕阶段）
```

## 规则文件组织

`undertale_preset` 的战斗规则按功能拆分为多个文件：

| 文件 | 职责 |
|------|------|
| `menu_navigation.fre.ron` | 方向键导航（主菜单、敌人列表、ACT 选项、物品网格） |
| `menu_confirm.fre.ron` | 确认键处理（层级跳转、行动执行） |
| `menu_cancel.fre.ron` | 取消键处理（返回上一层） |
| `fight_hit.fre.ron` | FIGHT 打击判定规则 |

所有这些文件在 `SpawnView` 时通过 View 的 FRE 配置自动加载，View 销毁时自动清理。
