# 使用 Alight Motion 制作弹幕

> 涉及 crate：`bevy_alight_motion`
>
> 涉及文件：`.amproj`、`alight_motion_config.ron`

## 概述

在 [1.2 编排弹幕演出](1.2_danmaku.serious.md) 中，我们学习了如何用 `.performance.ron` 手写弹幕。AM（Alight Motion）集成提供了
**另一种方式**：直接在序列中用一个 `AmPerformance` Chapter 替换 `DanmakuPerformance` Chapter，播放 AM 制作的动画作为弹幕。

**这不是对工作流的颠覆，而是在 RON 流程中替换一个步骤。**

```ron
// 之前：手写弹幕
DanmakuPerformance(
    performance: "states/battle/danmaku/demo_attack.performance.ron",
),

// 替换为：AM 动画弹幕
AmPerformance(
    project: "states/battle/demo_turn.amproj",
    config: "states/battle/alight_motion_config.ron",
),
```

其余的战斗流程（加载敌人、菜单交互、FRE 规则等）完全不变。

### 何时使用 AM

| 场景               | 推荐方式                              |
|------------------|-----------------------------------|
| 规律性弹幕（环形散射、线性阵列） | `.performance.ron` — 程序化更精确       |
| 自机狙、随机攻击、动态行为    | `.performance.ron` — AM 无法实现运行时逻辑 |
| 精心编排的视觉演出        | `.amproj` — 可视化编辑更直观              |
| 社区动画制作者参与弹幕设计    | `.amproj` — 降低门槛，无需学习 RON         |
| 复杂的多阶段攻击组合       | **混用** — 同一场战斗中两种方式并存             |

**关键限制**：AM 动画是预录制的时间线，不包含运行时逻辑。自机狙（追踪玩家位置）、随机生成、条件触发等需要游戏逻辑的效果无法纯粹通过
AM 实现。

## 准备动画文件

### 制作要求

1. **内容以纯弹幕为主**——AM 动画的目标是替代 `.performance.ron`，不是替代整个 View
2. **战斗框可以选择**：
    - 使用 SoupRune 原生 SDF 战斗框（大多数情况推荐）
    - 在 AM 中定义战斗框图层（用 `#C` 前缀标记）
3. 导出为 `.amproj` 文件，放入 `projects/<mod>/assets/` 目录

### 图层命名约定

在 AM 中，通过图层命名标记哪些元素参与游戏逻辑：

| 默认前缀 | 含义                           |
|------|------------------------------|
| `#B` | **弹幕图层** — 该元素会获得碰撞体，对玩家造成伤害 |
| `#C` | **战斗框图层** — 定义玩家可移动区域的边界     |
| 无前缀  | 纯视觉装饰，不参与碰撞                  |

没有特殊前缀的图层只是视觉效果——烟雾、粒子、背景装饰等。

## 配置文件

每个 AM 弹幕需要一个配置文件来告诉框架如何将动画元素映射为游戏对象：

```ron
(
    scale: 2.0,                    // 整体尺寸倍率
    offset: (0.0, 0.0),           // 位置偏移（相对于战斗框中心）
    bullet_pattern: "^#B",        // 正则：匹配弹幕图层名
    battle_box_pattern: "^#C",    // 正则：匹配战斗框图层名
    hidden_pattern: "^#B",        // 正则：隐藏原始视觉（用碰撞体替代）
    bullet_damage: 1.0,           // 每个弹幕的伤害值
    collision_scale: 0.05,        // 碰撞体缩放因子（AM 图形有大量透明边距）
)
```

`collision_scale` 之所以设置得很小，是因为 UT/DR 社区制作的 AM 的动画素材尺寸，往往包含大量透明区域，实际可见部分远小于元素边界。若您的动画并非如此，那么按实际情况调整即可。

## 在序列中使用

```ron
#![enable(implicit_some)]
(
    mode: "battle",
    chapters: [
        // ... 加载敌人、生成 UI、菜单交互等（同 1.1）...

        // 生成玩家
        SetPlayer(Spawn(
            config_path: "states/battle/players/player.battle_player.ron",
            position: (0.0, -80.0),
        )),

        // 播放 AM 弹幕（替代 DanmakuPerformance）
        AmPerformance(
            project: "states/battle/demo_turn.amproj",
            config: "states/battle/alight_motion_config.ron",
        ),

        // AM 动画播放完毕后，继续后续流程
        SetPlayer(Despawn),
        // ...
    ],
)
```

### 混用示例

同一场战斗中先播放 AM 动画，再接程序化弹幕：

```ron
chapters: [
    // 第一波：AM 制作的精致演出
    AmPerformance(
        project: "states/battle/wave1.amproj",
        config: "states/battle/alight_motion_config.ron",
    ),

    Wait(0.5),

    // 第二波：程序化自机狙（AM 无法实现）
    DanmakuPerformance(
        performance: "states/battle/danmaku/homing_attack.performance.ron",
    ),

    Wait(8.0),
]
```

## 技术细节

### ECS 实体化

`bevy_alight_motion` 将 AM 项目中的每个图层转换为独立的 Bevy ECS 实体。这意味着：

- 弹幕图层的碰撞检测由 Bevy 物理系统处理
- 图层的父子关系映射为 ECS 的实体层级
- 图层的生命周期（入/出时间）由 ECS 系统管理

### SDF 渲染

矢量图形（Shape 图层）使用自定义 SDF 着色器渲染：描边宽度在缩放时保持恒定，支持 multiply/screen/overlay 等混合模式。

### 坐标转换

AM 使用左上角原点 `(0, 0)`，Bevy 使用中心原点。`bevy_alight_motion` 自动处理坐标转换和 Y 轴翻转。

### 播放控制

运行时可通过 `AmPlayback` 资源控制速度、暂停、循环等：

| 字段                | 类型     | 说明             |
|-------------------|--------|----------------|
| `current_time_ms` | `f32`  | 当前播放位置（毫秒）     |
| `playing`         | `bool` | 是否播放           |
| `speed`           | `f32`  | 速度倍率（1.0 = 正常） |
| `looping`         | `bool` | 是否循环           |

### 支持的特效

`bevy_alight_motion` 支持 40+ 种 AM 特效的实时渲染，包括重复、径向重复、擦除效果、镜像、像素化、RGB 分离等。完整特效列表请参见
`bevy_alight_motion` 的文档。
