# FRE + Sequencer 进阶

## 概述

SoupRune 的运行时逻辑由两个系统协作驱动：

- **FRE（Fact-Rule-Event）**：数据驱动的规则系统，处理"当 X 发生时，如果 Y 成立，则执行 Z"
- **Sequencer**：线性/分支流程编排器，处理"按顺序执行 A → B → C"

二者的分工：**Sequencer 是导演，FRE 是演员**。Sequencer 决定场景的大流程（加载资源 → 播放开场 → 进入战斗循环），FRE 处理场景内的交互细节（按键响应、菜单导航、对话触发）。

> 关于 FRE 的基本概念（Fact/Rule/Event 三层架构），请参阅 [[1.4_act|编写交互逻辑]] 中的介绍部分。本文聚焦于**进阶用法和 Sequencer 集成**。

## Sequencer 基础

### `.sequence.ron` 文件结构

```ron
(
    mode: "battle",
    chapters: [
        SetCamera(SetZoom(2.0)),
        LoadEnemies(enemies: [ "data/enemies/dummy.enemy.ron" ]),
        SpawnView(
            view_layout: "states/battle/view/undertale.view.ron",
            bindings: { "enemies": LocalLayer },
        ),
        AwaitFact(condition: "$selection_confirmed == true"),
        RunSequence(path_fact: "pending_sequence"),
        DanmakuPerformance(performance: "danmaku/demo.performance.ron"),
    ],
)
```

`mode` 决定激活哪些运行时系统。`chapters` 是一个有序列表，Sequencer 按顺序执行每个 Chapter。

### Chapter 类型速查

#### 流程控制

| Chapter | 用途 |
|---------|------|
| `Sequence([...])` | 按顺序执行子章节 |
| `Parallel([...])` | 并行执行子章节（所有完成后继续） |
| `Wait(秒)` | 等待指定时间 |
| `AwaitFact(condition)` | 阻塞直到条件成立 |
| `Conditional { condition, then_branch, else_branch }` | 条件分支 |
| `FactSwitch { fact_key, cases, default }` | 多值分支 |
| `RunSequence { path, path_fact, params }` | 调用另一个 `.sequence.ron` |
| `Log { text, level }` | 输出调试日志 |

#### 资源加载

| Chapter | 用途 |
|---------|------|
| `LoadEnemies(enemies: [...])` | 加载敌人定义文件 |
| `LoadFre { files, aggregate }` | 动态加载 FRE 规则 |
| `LoadMap { path }` | 加载 Tiled 地图 |
| `SetBgm { path, fade_in }` | 设置/切换背景音乐 |

#### View 与 UI

| Chapter | 用途 |
|---------|------|
| `SpawnView { view_layout, bindings }` | 生成 View |
| `SetViewFact { key, value }` | 修改 View 局部 Fact |
| `TweenViewElement { selector, target, duration, easing }` | View 元素动画 |
| `ModifyViewElement { selector, modification }` | 即时修改 View 元素属性 |

#### 战斗系统

| Chapter | 用途 |
|---------|------|
| `DanmakuPerformance { performance }` | 播放弹幕演出 |
| `AlightMotionPerformance { amproj_path }` | 播放 AM 动画 |
| `SplitBattleBox { source, result, axis }` | 拆分战斗框 |
| `MergeBattleBoxes { sources, result }` | 合并战斗框 |
| `SetPlayer(action)` | 玩家实体操作（生成/销毁/移动） |
| `SetCamera(action)` | 摄像机操作（缩放/移动） |

#### Fact 操作

| Chapter | 用途 |
|---------|------|
| `EmitFactEvent { event_id }` | 发出 FRE 事件 |
| `ModifyFact { modifications }` | 批量修改 Fact |

#### 扩展

| Chapter | 用途 |
|---------|------|
| `SpawnBehavior { behavior_id }` | 生成 WASM 行为实体 |
| `Custom { action_type, params }` | 自定义扩展动作 |

## 深入 Sequencer

### `AwaitFact`：等待条件

Sequencer 最重要的阻塞机制。暂停执行直到指定的 Fact 条件满足：

```ron
// 等待玩家确认选择
AwaitFact(condition: "$selection_confirmed == true"),

// 等待 View 规则加载完成（local: true 表示检查 View 局部 Fact）
AwaitFact(condition: "$view_rules_loaded == true", local: true),

// 等待对话结束
AwaitFact(condition: "$dialogue:active == false", local: false),
```

`local: true`（默认）检查 View 局部 Fact，`local: false` 检查全局/分层 Fact。

### `RunSequence`：序列复用

调用另一个 `.sequence.ron` 文件，实现流程模块化：

```ron
// 通过固定路径调用
RunSequence(path: "states/battle/common/narration.sequence.ron"),

// 通过 Fact 值动态调用（FRE 规则设置 pending_sequence 的路径）
RunSequence(path_fact: "pending_sequence"),

// 传递参数
RunSequence(
    path: "states/battle/common/show_narration.sequence.ron",
    params: { "narration_key": String("act_check_result") },
),
```

`path_fact` 是最灵活的方式——FRE 规则根据玩家选择设置不同的序列路径，Sequencer 只需要执行"待处理的序列"。

### `TweenViewElement`：View 动画

对 View 元素做平滑过渡动画：

```ron
// 改变战斗框大小
TweenViewElement(
    selector: LocalName("BattleBox"),
    target: BoxSize(to: (130, "@current")),
    duration: 0.85,
    easing: QuadInOut,
    wait_for_completion: false,
),

// 移动位置
TweenViewElement(
    selector: LocalName("BattleBox"),
    target: Position(to: ("@current", "@current + 80", "@current")),
    duration: 1.0,
    easing: CubicOut,
    wait_for_completion: true,
),
```

`@current` 引用元素的当前值。`wait_for_completion` 控制是否等动画结束再继续。

### `Conditional` 和 `FactSwitch`：分支

```ron
// 二元条件
Conditional(
    condition: Equals(key: "act_type", value: String("check")),
    then_branch: RunSequence(path: "acts/check.sequence.ron"),
    else_branch: RunSequence(path: "acts/default.sequence.ron"),
),

// 多值分支
FactSwitch(
    fact_key: "act_type",
    cases: [
        (String("check"), RunSequence(path: "acts/check.sequence.ron")),
        (String("talk"), RunSequence(path: "acts/talk.sequence.ron")),
        (String("flirt"), RunSequence(path: "acts/flirt.sequence.ron")),
    ],
    default: Log(text: "Unknown act type"),
),
```

## FRE 规则进阶

### 规则文件结构

```ron
#![enable(implicit_some)]

(
    scope: View,

    enums: {
        "depth": ["main", "submenu", "options"],
        "menu_context": ["fight", "act", "item", "mercy"],
    },

    rules: [
        (event: ActionEvent(action: "Confirm", kind: JustPressed),
         conditions: ["$interactable == true", "$depth == 'main'"],
         actions: [
             SetLocalFact("menu_context", Expr("$button_selection")),
             SetLocalFact("depth", Enum("submenu")),
             PlaySound("confirm"),
         ]),
    ],
)
```

### `scope`

| 值 | 含义 |
|------|------|
| `View` | 规则绑定到 View 局部 Fact 层，`SetLocalFact` 修改 View 局部 Fact |
| `Global` | 规则作用于全局 Fact |
| （省略） | 默认为 `Global` |

### `enums`

为 Fact 值定义枚举别名。`depth == 'main'` 等价于 `depth == 0`，但更易读。定义后可在 conditions 和 actions 中使用字符串别名。

### 事件类型

| 事件 | 说明 |
|------|------|
| `ActionEvent(action, kind)` | 输入动作事件（`JustPressed` / `Pressed` / `JustReleased`） |
| `Event(event_id)` | 自定义事件（由 `EmitFactEvent` 或代码触发） |

`ActionEvent` 的 `action` 值对应输入配置中定义的动作名（如 `"Confirm"`, `"Left"`, `"Right"` 等）。

### 动作类型

| 动作 | 说明 |
|------|------|
| `SetLocalFact(key, value)` | 修改 View 局部 Fact |
| `PlaySound(path)` | 播放音效 |
| `EmitEvent(event_id)` | 发出新事件 |
| `StartDialogue { mortar, node, ... }` | 启动 Mortar 对话 |
| `UseItem(index_expr)` | 使用道具 |
| `CloseView` | 关闭当前 View |
| `SwitchState(state)` | 切换应用状态 |

### Fact 值表达式

`Expr(...)` 允许在动作中使用表达式：

```ron
// 简单运算
SetLocalFact("selection", Expr("$selection + 1"))

// 数组索引
SetLocalFact("current_name", Expr("$enemy_names[$enemy_selection]"))

// 嵌套变量引用（$$ 语法）
SetLocalFact("act_count", Expr("$${current_enemy_id}.act_count"))
```

`$${}` 语法先求值 `current_enemy_id` 的值（比如 `"dummy"`），然后引用 `$dummy.act_count`。

## FRE + Sequencer 协作模式

### 战斗回合循环

典型的 Undertale 风格战斗流程：

```
Sequencer (demo.sequence.ron)
│
├── LoadEnemies(...)          // 加载敌人数据
├── SpawnView(...)            // 生成战斗 UI
├── AwaitFact("$view_rules_loaded == true")
├── EmitFactEvent("battle:show_intro")  // FRE 规则触发开场对话
├── SetViewFact("interactable", true)   // 启用菜单
│
├── AwaitFact("$selection_confirmed == true")  // 等待玩家选择
│   │
│   │  [FRE 规则在此期间处理输入]
│   │  ├── Left/Right → 移动选择光标
│   │  ├── Confirm in main → 进入子菜单
│   │  ├── Confirm in submenu → 设置 pending_sequence
│   │  └── Cancel → 返回上级菜单
│   │
├── RunSequence(path_fact: "pending_sequence")  // 执行玩家选择的动作
│   │  （可能是 narration.sequence.ron、fight_target.sequence.ron 等）
│   │
├── SetViewFact("interactable", false)
├── SetPlayer(Spawn(...))
├── TweenViewElement(BattleBox, BoxSize(...))  // 缩小战斗框
├── DanmakuPerformance(...)                    // 弹幕阶段
├── SetPlayer(Despawn)
├── TweenViewElement(BattleBox, BoxSize(...))  // 恢复战斗框
└── [下一回合...]
```

### 关键设计模式

**1. FRE 设置，Sequencer 执行**

FRE 规则负责决定"做什么"（通过设置 `pending_sequence` Fact），Sequencer 负责"怎么做"（通过 `RunSequence(path_fact: ...)` 执行）。

```ron
// FRE 规则：玩家在 ACT 菜单按确认
(event: ActionEvent(action: "Confirm", kind: JustPressed),
 conditions: ["$depth == 'options'", "$menu_context == 'act'"],
 actions: [
     SetLocalFact("pending_sequence", Expr("$${current_enemy_id}.action_sequences[$act_selection]")),
     SetLocalFact("selection_confirmed", Bool(true)),
 ]),
```

```ron
// Sequencer：执行 FRE 设置的序列
AwaitFact(condition: "$selection_confirmed == true"),
RunSequence(path_fact: "pending_sequence"),
```

**2. Sequencer 控制阶段，FRE 控制细节**

```ron
// Sequencer 控制阶段切换
SetViewFact(key: "interactable", value: Bool(true)),   // 开启交互
AwaitFact(condition: "$selection_confirmed == true"),    // 等待结果
SetViewFact(key: "interactable", value: Bool(false)),  // 关闭交互
```

`interactable` Fact 充当开关——FRE 规则检查 `$interactable == true` 才响应输入。

**3. 可复用序列模板**

通用模式（如"播放对话 → 等待结束"）提取为独立文件：

```ron
// narration.sequence.ron — 通用 Mortar 对话模板
(chapters: [
    EmitFactEvent(event_id: "dialogue:stop"),
    SetViewFact(key: "narration_visible", value: Bool(true)),
    ModifyFact(modifications: [
        Set(key: "dialogue:pending_mortar_path", value: Expr("$mortar_path")),
        Set(key: "dialogue:pending_mortar_node", value: Expr("$action_param")),
        Set(key: "dialogue:pending_start", value: Bool(true)),
    ]),
    AwaitFact(condition: "$dialogue:active == true", local: false),
    AwaitFact(condition: "$dialogue:active == false", local: false),
    SetViewFact(key: "narration_visible", value: Bool(false)),
])
```

FRE 规则在调用前设置 `mortar_path` 和 `action_param`，然后 Sequencer 通过 `RunSequence` 执行这个模板。

## 实战：添加新的战斗回合逻辑

假设你要添加"检查后随机触发特殊事件"：

### 1. 创建特殊事件序列

```ron
// states/battle/acts/special_event.sequence.ron
(chapters: [
    SetViewFact(key: "narration_visible", value: Bool(true)),
    SetViewFact(key: "dialogue_text", value: String("* Something special happened!")),
    AwaitFact(condition: "$confirm_pressed == true"),
    SetViewFact(key: "confirm_pressed", value: Bool(false)),
    SetViewFact(key: "narration_visible", value: Bool(false)),
])
```

### 2. 在 FRE 规则中添加触发条件

```ron
// 特殊事件规则（仅在特定条件下触发）
(event: ActionEvent(action: "Confirm", kind: JustPressed),
 conditions: [
     "$depth == 'options'",
     "$menu_context == 'act'",
     "$special_event_ready == true",
 ],
 actions: [
     SetLocalFact("pending_sequence", String("states/battle/acts/special_event.sequence.ron")),
     SetLocalFact("selection_confirmed", Bool(true)),
     SetLocalFact("special_event_ready", Bool(false)),
 ],
 priority: 20,  // 高于普通 ACT 规则的优先级
),
```

### 3. 在主序列中设置触发条件

```ron
// 在战斗开始时随机设置
ModifyFact(modifications: [
    Set(key: "special_event_ready", value: Bool(true)),
]),
```

这就是 FRE + Sequencer 的协作方式：**Sequencer 建立舞台，FRE 导演表演**。
