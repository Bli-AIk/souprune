# View 系统

## 概述

View 是 SoupRune 的 **RON 驱动声明式 UI 系统**。它的核心思想是：**用数据文件定义界面，用 FRE 规则驱动状态变化**。

开发者通过 `.view.ron` 文件描述界面的结构、样式和数据绑定，View 系统负责将这些声明渲染为屏幕上的实际元素。所有运行时状态（菜单层级、选中项、文本内容）都存储在 FRE Fact 中，通过规则响应玩家输入。

### 核心特性

- **声明式布局**：RON 文件定义 UI 树，无需编写 Rust 代码
- **FRE 集成**：`visible_when` 表达式根据 Fact 控制元素显隐
- **动态文本**：`{{fact_key}}` 模板实时绑定数据
- **SDF 渲染**：基于 Signed Distance Field 的矢量化 UI 盒子
- **热重载**：调试模式下修改 `.view.ron` 文件后自动更新（无需重启）

## 文件格式：`.view.ron`

一个完整的 View 布局文件包含三个部分：

```ron
#![enable(implicit_some)]

(
    world_space: true,

    // 1. 数据依赖
    requires: [
        File("states/battle/rules/menu_navigation.fre.ron"),
        File("states/battle/rules/menu_confirm.fre.ron"),
        Interface(
            interface: "enemies",
            expects: [
                "enemy_ids: StringList",
                "enemy_names: StringList",
                "enemy_hps: IntList",
            ],
        ),
    ],

    // 2. 初始 Fact 状态
    facts: {
        "depth": 0,
        "button_selection": 0,
        "dialogue_text": "",
        "interactable": false,
    },

    // 3. 视觉节点树
    roots: [
        (
            name: "BattleBox",
            view_box: ( ... ),
            texts: [ ... ],
            children: [ ... ],
        ),
    ],
)
```

### `requires`：数据依赖

| 类型 | 用途 |
|------|------|
| `File(path)` | 加载 FRE 规则文件（`.fre.ron`） |
| `Interface(interface, expects)` | 声明数据接口（由 Sequencer 的 `SpawnView` 绑定实际数据） |

`Interface` 用于解耦数据来源。例如战斗 View 声明"我需要敌人名称列表"，具体数据由 Sequencer 在 `SpawnView` 时通过 `bindings` 注入。

### `facts`：View 局部 Fact

View 拥有独立的 Fact 层（View Layer），与全局 Fact 隔离。这些 Fact 只在当前 View 的生命周期内存在：

```ron
facts: {
    "depth": 0,                // 菜单层级：0=主菜单, 1=子菜单, 2=选项
    "button_selection": 0,     // 当前选中按钮
    "dialogue_text": "",       // 打字机显示的文本
    "interactable": false,     // 是否接受输入
    "narration_visible": false, // 旁白区域是否可见
},
```

FRE 规则通过 `SetLocalFact` 修改这些值，View 系统自动响应更新。

## 视觉节点

### 基本结构

每个节点可以包含以下元素：

```ron
(
    name: "MenuButton",
    visible_when: "$depth == 0",
    view_box: (
        width: 100.0,
        height: 40.0,
        border_width: 3.0,
        offset: (0.0, 0.0, 0.0),
        structure_file: "shared/view_structures/view_box.sdf.ron",
    ),
    texts: [
        (
            id: "ButtonLabel",
            content: "FIGHT",
            font: DeterminationMono,
            world_scale: (26.0, 26.0),
            color: (1.0, 1.0, 1.0, 1.0),
            transform: (translation: (0.0, 0.0, 1.0)),
        ),
    ],
    children: [ ... ],
)
```

### `visible_when`：条件可见性

最核心的特性。表达式在每帧求值，决定节点是否显示：

```ron
// 仅在主菜单层级显示
visible_when: "$depth == 0"

// 组合条件
visible_when: "$depth == 0 && $dialogue_visible == true && $narration_visible == false"

// 在 repeat 循环中使用索引
visible_when: "$depth == 1 && $menu_context == 0 && @i >= $enemy_view_offset"
```

**表达式语法：**

| 语法 | 含义 |
|------|------|
| `$variable` | 读取 View 局部 Fact |
| `@i` | `repeat` 循环的当前索引 |
| `==`, `!=`, `>`, `<`, `>=`, `<=` | 比较运算 |
| `&&`, `\|\|` | 逻辑运算 |
| `floor()`, `max()`, `min()` | 内置函数 |

### `view_box`：SDF 渲染盒子

View 系统使用 SDF（Signed Distance Field）技术渲染 UI 边框和填充区域，而非传统的九宫格切片。

```ron
view_box: (
    width: 566.0,
    height: 130.0,
    border_width: 5.0,
    offset: (0.0, -80.0, 0.0),
    structure_file: "shared/view_structures/view_box.sdf.ron",
    fill_color: (0.0, 0.0, 0.0, 1.0),
),
```

`structure_file` 指向一个 `.sdf.ron` 文件，定义盒子的层级结构（外边框 + 内填充）。

### `texts`：文本元素

```ron
texts: [
    (
        id: "DialogueText",
        content: "{{dialogue_text}}",
        font: DeterminationMono,
        world_scale: (13.25, 13.25),
        color: (1.0, 1.0, 1.0, 1.0),
        transform: (translation: (-130.5, 27.85, 1.0)),
        line_height: 1.125,
        visible_when: "$dialogue_visible == true",
    ),
],
```

`content` 支持两种模板语法：

**简单替换：** `{{fact_key}}` — 将 Fact 的值直接插入
```ron
content: "{{dialogue_text}}"
content: "HP {{player_hp}} / {{player_hp_max}}"
```

**Lambda 表达式：** 遍历数组 Fact 生成列表
```ron
content: "{|name, i| in $enemy_names[0..$enemy_count] => \"* {name}\"}"
```

### `repeat`：动态列表

`repeat` 让一个节点定义变成多个实例，用于渲染敌人列表等动态内容：

```ron
(
    name: "EnemyEntry",
    repeat: (source: "enemy_names", index_var: "i"),
    visible_when: "@i >= $enemy_view_offset && @i < $enemy_view_offset + $enemy_display_limit",
    texts: [
        (
            id: "EnemyName",
            content: "{{enemy_names[@i]}}",
            ...
        ),
    ],
),
```

`source` 指定要遍历的数组 Fact，`index_var` 定义循环变量名。

## SDF 结构文件：`.sdf.ron`

SDF 结构文件定义 UI 盒子的视觉层级。经典的 Undertale 对话框是两层结构：

```ron
// shared/view_structures/view_box.sdf.ron
(
    layer_count: 2,
    root: (
        name: "UIBoxBorder",
        sdf_type: Outer,
        color_source: White,
        z_offset: 5.0,
        is_filler: false,
        children: [
            (
                name: "UIBoxFiller",
                sdf_type: Inner,
                color_source: FillColor,
                z_offset: 0.1,
                is_filler: true,
                children: [],
            ),
        ],
    ),
)
```

| 属性 | 说明 |
|------|------|
| `sdf_type: Outer` | 外层形状（边框） |
| `sdf_type: Inner` | 内层形状（填充，比外层小 `border_width`） |
| `color_source: White` | 固定白色 |
| `color_source: FillColor` | 使用 `view_box.fill_color` |
| `color_source: Custom(r, g, b, a)` | 自定义颜色 |
| `is_filler: true` | 标记为文本/子元素的渲染区域 |

### Fact 驱动颜色切换

SDF 层的颜色可以根据 Fact 值动态变化：

```ron
// shared/view_structures/attack_bar.sdf.ron
(
    layer_count: 2,
    root: (
        name: "AttackBarOuter",
        sdf_type: Outer,
        color_source: FactToggle(
            key: "fight:bar_flash_on",
            on: (1.0, 1.0, 1.0, 1.0),
            off: (0.0, 0.0, 0.0, 1.0),
        ),
        ...
    ),
)
```

当 `fight:bar_flash_on` 为 `true` 时显示白色，为 `false` 时显示黑色。

## View 生命周期

### 1. 生成（Spawn）

View 通过 Sequencer 的 `SpawnView` 章节创建：

```ron
SpawnView(
    view_layout: "states/battle/view/undertale.view.ron",
    bindings: {
        "enemies": LocalLayer,
    },
),
```

`bindings` 将 `Interface` 声明的数据接口绑定到实际数据源。`LocalLayer` 表示从 Sequencer 的局部 Fact 层读取。

### 2. 运行

- **FRE 规则**处理输入事件，修改 View 局部 Fact
- **View 系统**每帧求值 `visible_when`，更新元素可见性
- **动态文本**每帧求值 `{{}}` 模板，更新显示内容
- **SDF 颜色**根据 `FactToggle` 的 Fact 值切换

### 3. 销毁

当拥有 View 的 Sequencer 结束或切换状态时，View 及其所有实体被自动清理。

## View + FRE 协作模式

View 系统**不包含任何输入处理逻辑**。所有交互通过 FRE 规则实现：

```
玩家按下方向键
    ↓
FRE 规则匹配 ActionEvent("Right", JustPressed)
    ↓
条件检查：$interactable == true && $depth == 'main' && $button_selection < 3
    ↓
动作执行：SetLocalFact("button_selection", Expr("$button_selection + 1"))
    ↓
View 系统检测到 button_selection 变化
    ↓
重新求值所有 visible_when 表达式 → 光标移动
```

这种分离设计的优势：
- **可配置**：更换按键映射不需要修改 View
- **可测试**：规则可以独立于 UI 验证
- **可复用**：同一套规则可以驱动不同的 View 布局

## 实战示例：最小战斗 View

```ron
#![enable(implicit_some)]

(
    world_space: true,
    requires: [
        File("rules/my_navigation.fre.ron"),
    ],
    facts: {
        "depth": 0,
        "selection": 0,
        "dialogue_text": "* A wild monster appears!",
    },
    roots: [
        (
            name: "DialogueBox",
            view_box: (
                width: 283.0,
                height: 70.0,
                border_width: 3.0,
                offset: (0.0, -78.0, 0.0),
                structure_file: "shared/view_structures/view_box.sdf.ron",
            ),
            texts: [
                (
                    id: "MainText",
                    content: "{{dialogue_text}}",
                    font: DeterminationMono,
                    world_scale: (13.25, 13.25),
                    color: (1.0, 1.0, 1.0, 1.0),
                    transform: (translation: (-130.5, 27.85, 1.0)),
                ),
            ],
        ),
    ],
)
```

这是一个只包含对话框的最小 View。文本内容通过 `dialogue_text` Fact 驱动，可以由 Mortar 对话系统或 Sequencer 的 `SetViewFact` 更新。
